# 整改说明与验证记录

## 整改对象

现有 `dvwa_sqli_scanner.py` 能够对 GET Query 参数发送 SQL 注入 Payload，但扫描器自身缺少授权边界、凭据保护、资源限制和安全报告机制。本次整改在保留课程靶场检测能力的同时，解决扫描工具可能带来的信息安全风险。

## 整改一：未授权扫描与 SSRF

### 问题

原工具对用户提供的 URL 直接发起请求，允许公网、内网或云元数据地址，且会自动跟随重定向。

### 修改

- 新增 JSON 授权策略。
- 在主机名、DNS 解析 IP、IP 类型、网段、端口和路径六个层面校验。
- 拒绝公网、link-local、multicast、unspecified 与未授权地址。
- 禁止 HTTP 自动重定向，并在每次请求前重新校验目标。

### 达成条件

只有授权配置明确允许的本地 DVWA 目标能发出请求，任一边界不匹配即中止。

### 验证

公网主机、公网 IP、`169.254.169.254`、URL 内嵌凭据、路径穿越、非 HTTP Scheme 和 HTTP 302 用例均通过。

## 整改二：Cookie 泄露与请求头注入

### 问题

原工具要求通过 `--cookie` 传入明文 Cookie，值可能留在 Shell 历史和进程列表中；宽松解析会忽略非法片段。

### 修改

- 取消明文 `--cookie` 入口，改为隐藏输入或指定环境变量。
- 拒绝控制字符、非法 Cookie 名称、缺少等号和重复 Cookie 名称。
- 禁用环境 HTTP 代理，避免 Cookie 离开本地靶场。
- 报告数据模型不接收 Cookie，从结构上减少误写风险。

### 达成条件

Cookie 不出现在命令行、终端摘要、JSON 报告或 Markdown 报告中，包含 CR/LF 的 Cookie 在发请求前被拒绝。

### 验证

4 项 Cookie 格式用例和 1 项报告脱敏用例通过。测试使用标记字符串，确认该字符串不出现在两种报告中。

## 整改三：资源消耗与扫描强度

### 问题

原工具没有全局请求上限、最小请求间隔和响应体大小上限，并默认发送 `SLEEP` Payload。

### 修改

- 配置并强制执行请求次数、间隔、超时、响应大小和参数数量上限。
- 响应只读取「配置上限 + 1」字节，超额后不继续处理。
- 延时测试默认关闭，需要配置与 CLI 双重授权。

### 达成条件

请求或响应超出策略后进入可记录的安全中止状态，不继续攻击性测试。

### 验证

使用本地 HTTP 测试服务验证 4096 字节大响应会被 1024 字节策略拒绝，第二个请求会被单次额度策略拒绝。

## 整改四：误报、证据与报告

### 问题

原工具对单次基线做响应长度判断，证据容易受动态内容影响，且只在终端输出文本，不便于追溯。

### 修改

- 基线重复采样两次。
- 增加布尔真/假 Payload 成对差分与基线接近度判断。
- 结果包含类型、置信度、简化证据和状态码。
- 报告使用临时文件、`fsync`、`os.replace` 和 `0600` 权限。
- 报告输出路径限制在个人 `reports/` 内。

### 达成条件

可疑点必须包含可复核证据，不使用「绝对安全」或「已确认漏洞」的过度结论；报告不泄露凭据和原始响应。

### 验证

可控响应测试同时检出 SQL 报错证据和布尔差分证据；报告权限、Cookie 脱敏与 Query 值脱敏用例通过。

## 整改过程中发现的二次问题

AI 生成初稿后，自动化测试和人工审查又发现并修复：

- HTTP 302 异常响应未显式关闭。
- IPv6 回环地址被通用保留地址判断误拒绝。
- `urllib` 默认环境代理可能导致 Cookie 离开靶场边界。
- Query 解码后控制字符和报告输出路径缺少限制。
- 示例配置未包含仓库 DVWA Compose 实际使用的 4280 端口。

## 最终验证结论

- 20 项自动化安全测试通过。
- `compileall` 通过。
- 公网 URL 命令行调用按预期安全中止。
- `git diff --check` 通过。
- 执行环境中 Docker 守护进程未运行，因此没有伪造真实 DVWA 扫描结果；启动靶场后按 README 使用隐藏 Cookie 输入即可补充集成报告。
