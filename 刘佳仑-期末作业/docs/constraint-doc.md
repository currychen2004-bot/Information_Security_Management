# 项目约束文档

## 背景说明

项目需要对现有 DVWA SQL 注入简易扫描工具进行安全加固。工具会向目标发送攻击性测试输入，并使用登录 Cookie，因此必须同时管理扫描授权、网络边界、凭据、资源消耗和证据输出。

## 任务范围

- 在 `刘佳仑-期末作业/` 中实现新的模块化扫描器，不修改 DVWA 靶场源码。
- 保留对 GET Query 参数的 SQL 注入启发式检测。
- 新增授权范围策略、安全 HTTP 客户端、凭据保护、结果分级和脱敏报告。
- 使用 Python 标准库实现，不引入不必要的第三方依赖。
- 提供可离线运行的自动化安全测试。

## 必须遵守的安全约束

### 目标与授权

- 采用默认拒绝策略；只有配置文件显式允许的主机、IP 网段、端口和路径才能扫描。
- URL Scheme 只能是 `http` 或 `https`，不得在 URL 中携带用户名或密码。
- 主机名必须解析为允许网段内的 IP；解析失败、混合解析或任一 IP 越界时均拒绝。
- 禁止自动跟随 HTTP 重定向。

### 凭据与输入

- 不得通过明文命令行参数接收 Cookie；只能通过隐藏输入或指定环境变量提供。
- Cookie 名称必须符合 HTTP Token 格式，名称和值均不得包含控制字符、回车或换行。
- 对超时、响应上限、请求间隔、请求数量和 Query 参数数量进行范围校验。
- 错误信息只说明失败类型，不输出 Cookie、响应原文或本地敏感路径。

### 请求与资源

- 每次请求前检查全局请求额度，请求之间执行最小间隔。
- 响应采用有界读取，超过上限后中止，不得将无界响应全部读入内存。
- 默认不发送延时 Payload。延时测试必须由配置文件和命令行双重授权。
- 不禁用 TLS 证书验证，不增加绕过 HTTPS 校验的选项。

### 检测与报告

- 安全控制必须落实在代码执行路径中，不能只写在注释或 README 中。
- 漏洞结果使用「可疑点」和置信度表达，不得仅凭单次响应宣称已确认漏洞。
- 报告中不保存 Cookie、Cookie 来源环境变量的值或完整响应体。
- 报告使用同目录临时文件加 `os.replace` 原子写入，文件权限设为仅当前用户可读写。

## 禁止行为

- 禁止将真实 Cookie、密码、Token 或密钥写入代码、配置示例、测试、文档和 Git 提交。
- 禁止提供「跳过授权校验」或「允许任意目标」开关。
- 禁止默认扫描公网、云元数据服务、广播、组播或未授权内网地址。
- 禁止默认执行延时或高强度 Payload。
- 禁止在报告中嵌入未经脱敏的原始 HTTP 请求和响应。
- 禁止为通过测试而绕过 DNS、IP、重定向或请求额度校验。

## 验收条件

- 合法的本地 DVWA URL 可以进入扫描流程。
- 未在白名单中的主机、端口、路径或 IP 网段被拒绝。
- 未授权重定向、超大响应和请求超额会导致安全中止。
- 测试 Cookie 不出现在终端文本、JSON 报告或 Markdown 报告中。
- 自动化测试覆盖上述关键边界，所有测试通过。

## 新对话使用规则

每次开启新的 AI 对话时，必须完整提供本文档的背景说明、任务范围、安全约束和禁止行为，不得仅用「注意安全」代替具体要求。
