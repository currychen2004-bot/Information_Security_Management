# 安全审查清单

## 第一层：对照 Prompt 与约束检查

| 检查项 | 结果 | 实现或证据 |
| --- | --- | --- |
| 是否在个人作业目录内完成实质性改造 | 通过 | 新增 `scanner/`、`tests/`、`config/`、`docs/` 和 `reports/` |
| 是否采用默认拒绝的目标授权策略 | 通过 | `ScopePolicy.validate_url` 同时检查主机、IP、端口和路径 |
| 是否拒绝公网与云元数据地址 | 通过 | 拒绝 global、link-local、multicast、unspecified 和未授权网段 |
| 是否阻止重定向越界 | 通过 | `NoRedirectHandler` 禁止所有自动重定向 |
| 是否避免 Cookie 出现在命令行 | 通过 | 仅支持 `--prompt-cookie` 或 `--cookie-env`，未提供 `--cookie` |
| 是否防止 Cookie 请求头注入 | 通过 | `parse_cookie` 拒绝控制字符、非法名称、缺失等号和重复名称 |
| 是否避免环境代理获取 Cookie | 通过 | HTTP opener 显式使用 `ProxyHandler({})` |
| 是否限制请求数与请求速率 | 通过 | 请求前检查 `max_requests`，通过单调时钟控制最小间隔 |
| 是否对响应进行有界读取 | 通过 | 最多读取 `max_response_bytes + 1`，超额后安全中止 |
| 是否校验 URL 与 Query 输入 | 通过 | 限制 Scheme、URL 长度、内嵌凭据、路径、参数数量、名称与值 |
| 延时测试是否默认关闭 | 通过 | 需要配置文件和 `--enable-time-tests` 双重允许 |
| 检测结果是否避免绝对定性 | 通过 | 结果包含 category、confidence 和 evidence，README 要求人工复核 |
| 报告是否脱敏 | 通过 | 仅保留参数名和脱敏目标，不保留 Cookie、Query 值和响应原文 |
| 报告是否安全写入 | 通过 | 临时文件、`fsync`、`os.replace`、`0600` 权限，且路径限于个人 `reports/` |

## 第二层：人工安全审查

| 检查领域 | 结果 | 审查结论 |
| --- | --- | --- |
| 授权边界 | 通过 | 策略在 CLI 启动和每次 HTTP 请求前均执行，不依赖用户自律 |
| 最小权限 | 通过 | 默认配置仅允许回环地址、DVWA SQLi 路径和指定端口 |
| 凭据生命周期 | 通过 | Cookie 只保存在当前进程内存中，不写入报告 |
| SSRF 防护 | 通过 | 白名单、DNS 结果检查、IP 类型检查和重定向阻断形成多层防护 |
| 资源管理 | 通过 | 超时、速率、请求额度、参数额度和响应上限均为有界数值 |
| 错误响应 | 通过 | 对用户只返回分类后的中止原因，不打印响应原文与 Cookie |
| 文件安全 | 通过 | 报告不能写到个人 `reports/` 以外，写入过程可原子替换 |
| 检测可靠性 | 基本通过 | 已改为两次基线和布尔成对比较，但启发式扫描仍可能误报或漏报 |

## 剩余风险

- 该工具仍是启发式扫描器，不能替代代码审计、手工复测和专业扫描平台。
- 主机名在策略检查和建立连接时会分别解析；本项目通过默认仅允许回环主机降低 DNS 重绑的实际风险。
- 真实 DVWA 集成验证需要 Docker 守护进程和登录 Cookie，本次自动执行环境中 Docker 未运行。
