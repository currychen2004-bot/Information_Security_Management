# Prompt 与 AI 协作记录

## 对话一：识别扫描器自身的安全风险

### 我的 Prompt

> 我计划对现有 DVWA SQL 注入扫描脚本进行安全加固。原脚本能够接收 URL 和 Cookie，并对 GET 参数发送 SQL 注入 Payload。我认为不能只改进漏洞检测准确率，还要管理扫描工具自身的滥用风险。请先不写代码，从扫描授权、SSRF、凭据保护、资源消耗、错误输出和结果留痕方面分析风险，并指出现有实现中的具体问题。

### AI 的回答摘要

AI 将问题分为以下七类：

1. 任意 URL 可能导致未授权扫描。
2. 域名解析、内网地址和 HTTP 重定向可能形成 SSRF 边界绕过。
3. `--cookie` 可能将会话凭据留在 Shell 历史和进程列表中。
4. Cookie 值缺少严格校验，存在请求头注入风险。
5. 无请求额度、速率和响应体上限，可能造成资源消耗。
6. 单次响应长度和延时判断证据不足，可能误报。
7. 终端输出缺少结构化报告和脱敏策略，不便于审查与留痕。

### 我的判断

我接受这一风险分类，并确定项目目标为「受控授权的 DVWA SQL 注入扫描器」。这样的改造不仅涉及检测功能，还覆盖授权、最小权限、输入处理、敏感数据、网络访问和安全审计。

## 对话二：将风险转化为结构化安全约束

### 我的 Prompt

> **背景：** 目标模块是一个面向本地 DVWA 的 GET 型 SQL 注入扫描器，会使用登录 Cookie 并发送攻击性测试输入。
>
> **任务范围：** 在个人作业目录中实现授权策略、安全 HTTP 客户端、SQL 注入证据分析、脱敏报告和自动化测试。
>
> **约束条件：** 目标必须匹配主机、IP 网段、端口和路径白名单；拒绝公网和云元数据地址；不自动跟随重定向；Cookie 只能通过隐藏输入或环境变量提供；必须限制请求数、速率、超时和响应体大小；报告不能包含 Cookie、Query 值和原始响应。
>
> **禁止行为：** 不硬编码凭据，不提供「允许任意目标」的绕过开关，不禁用 TLS 验证，不默认执行 `SLEEP` Payload，不仅在注释中声明安全要求。
>
> 请将这些约束转化为可实现、可测试的模块划分和验收条件。

### AI 的回答摘要

AI 建议拆分为五个责任模块：

- `policy.py`：读取授权配置，检查 URL、DNS、IP、端口和路径。
- `credentials.py`：严格解析 Cookie，拒绝控制字符和重复名称。
- `http_client.py`：阻断重定向，限制额度、速率、超时和响应大小。
- `detector.py`：执行基线、SQL 报错和布尔差分检测，生成置信度证据。
- `reporting.py`：生成脱敏 JSON/Markdown 报告，使用原子写入和限制性权限。

AI 同时建议将每项约束对应到自动化测试，避免安全功能只存在于 README。

## 对话三：审查 AI 的初始实现方案

### AI 的初始方案

AI 计划使用 JSON 白名单限制本地靶场，移除明文 `--cookie`，增加请求资源限制，并将延时检测设为可选功能。

### 我的审查 Prompt

> 这个方案还需要说清三个问题。第一，只检查主机名不足以防止 SSRF，必须检查 DNS 解析后的所有 IP。第二，合法 URL 可能重定向到越界目标，不能依赖 `urllib` 默认行为。第三，延时检测不能只有一个命令行开关，应该要求授权配置和当次命令双重允许。请修改设计，并给出对应测试。

### AI 的修正

- 配置中同时保存 `allowed_hosts`、`allowed_networks`、`allowed_ports` 和 `allowed_path_prefixes`。
- 解析到的任一 IP 不在授权网段或属于公网、link-local、multicast 等类型时，整个目标被拒绝。
- 通过 `NoRedirectHandler` 禁止所有自动重定向。
- 延时检测需要 `allow_time_based_tests=true` 与 `--enable-time-tests` 同时成立。
- 增加公网 IP、云元数据地址、重定向和延时检测授权用例。

## 对话四：要求 AI 实现并提供可审查证据

### 我的 Prompt

> 按照已确认的约束开始实现。要求只使用 Python 标准库，保留清晰的模块边界。对每一个安全控制，说明它落实在哪个执行路径，并编写能够验证「会拒绝什么」的测试。不要为了让测试通过而增加绕过开关。

### AI 生成结果中的关键片段

**默认拒绝的主机校验：**

```python
if hostname not in self.allowed_hosts:
    raise AuthorizationError("目标主机不在授权白名单中。")
```

**禁止代理和自动重定向：**

```python
self._opener = build_opener(ProxyHandler({}), NoRedirectHandler())
```

**有界读取响应：**

```python
raw = response.read(self.policy.max_response_bytes + 1)
if len(raw) > self.policy.max_response_bytes:
    raise SafetyLimitError("响应体超过授权策略中的大小上限。")
```

**延时检测双重授权：**

```python
if enable_time_tests and not client.policy.allow_time_based_tests:
    raise AuthorizationError("授权配置未允许延时检测。")
```

### 我的检查结论

上述控制均进入真实执行路径，不是只写在注释里。但 AI 生成完成不代表安全审查结束，仍需通过动态测试和人工阅读发现偏差。

## 对话五：根据测试和人工审查纠正 AI

### 偏差一：HTTPError 资源警告

**我的 Prompt：**

> 重定向阻断测试虽然通过，但出现了 `ResourceWarning`。不能忽略警告，请检查 HTTPError 响应是否在所有分支都会释放，修复后重新执行重定向用例。

**AI 的整改：** 将 HTTPError 处理改为 `try/finally`，在成功读取、重定向中止和响应超限等路径中均执行 `exc.close()`。复验后警告消失。

### 偏差二：IPv6 回环地址误拒绝

**我的 Prompt：**

> 配置已明确允许 `::1/128`，但通用 `is_reserved` 判断可能误拒绝 IPv6 回环地址。请区分「明确授权的 loopback」和「其他保留地址」，不要为了兼容 IPv6 而放宽公网或 link-local 限制。

**AI 的整改：** 对同时命中授权网段的 loopback 地址特别处理，其他禁止类型仍保持拒绝，并新增 IPv6 回归测试。

### 偏差三：环境代理与输入/输出边界

**我的 Prompt：**

> 请继续从敏感数据流向和文件写入边界审查。重点确认 `urllib` 是否会将带 Cookie 的请求交给环境代理，Query 解码后是否可包含控制字符，以及用户是否能将报告写到个人作业目录之外。

**AI 的整改：**

- 显式使用 `ProxyHandler({})` 禁用环境代理。
- 增加 URL、Query 名称和值的长度限制，拒绝解码后控制字符。
- 将报告路径限制在个人 `reports/` 目录内。
- 新增编码换行 Query 和报告路径越界验证。

### 偏差四：授权配置与实际环境不一致

**我的 Prompt：**

> 不要假设 DVWA 使用常见的 80 或 8080 端口。请读取仓库中的 Compose 配置，确认实际映射端口，并让默认授权范围与 README 运行命令保持一致。

**AI 的整改：** 确认仓库 DVWA 映射到 `127.0.0.1:4280`，将 4280 加入示例授权端口，并更新 README 执行命令。
