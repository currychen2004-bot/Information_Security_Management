# 风险分析记录

## 分析对象

本次作业基于现有的 `成员代码/DVWA SQL 注入简易扫描工具-刘佳仑/dvwa_sqli_scanner.py` 进行实质性安全加固。原工具接收 URL 和 Cookie，向目标的 GET 参数注入测试 Payload，再通过 SQL 报错、响应长度和响应时间判断可疑点。

改造目标是开发一个「受控授权的 DVWA SQL 注入扫描器」，在保留课程靶场检测能力的同时，对扫描目标、凭据、请求资源和报告进行安全管理。

## 敏感操作与资产

- 向目标发送包含 SQL 注入 Payload 的主动测试请求。
- 使用 DVWA 登录 Cookie，其中包含可复用的会话凭据。
- 解析用户提供的 URL、主机名、端口、路径和 Query 参数。
- 发起网络连接并读取服务端响应。
- 保存扫描目标、Payload、检测证据和错误信息。

## 主要安全风险

### 1. 未授权扫描

原工具接受任意 HTTP/HTTPS URL，没有目标范围校验。操作者输入公网地址后，工具会直接发送攻击性请求，可能超出课程授权范围。

### 2. SSRF 与重定向越界

如果工具被集成到其他服务，未受限制的 URL 可被用来访问公网、内网或云元数据地址。`urllib` 默认跟随重定向，即使初始 URL 合法，也可能跳转到授权范围外。

### 3. Cookie 和会话凭据泄露

原工具通过 `--cookie` 命令行参数传入 Cookie。Cookie 可能出现在 Shell 历史、进程列表、截图或错误日志中。Cookie 值如果允许换行，还可能导致 HTTP 请求头注入。

### 4. 资源消耗与拒绝服务

原工具没有全局请求上限、请求间隔和响应体上限，且默认执行 `SLEEP` 类 Payload。参数过多、服务端返回超大响应或延时 Payload 被频繁执行时，可能消耗本地与靶场资源。

### 5. 输入校验不完整

原工具未限制 URL Scheme、端口、路径、超时范围和 Query 参数数量；Cookie 解析遇到非法片段时直接忽略，不利于发现恶意或误配置输入。

### 6. 误报和不充分证据

单次响应长度变化可能来自随机页面内容或会话状态；单次延时也可能来自网络抖动。如果直接将启发式命中定性为漏洞，会影响安全决策的准确性。

### 7. 报告泄露与不安全写入

扫描报告如果记录完整 Cookie、包含敏感值的 URL 或原始响应，会形成二次泄露。直接覆盖报告文件还可能在进程中断时留下不完整结果。

## 安全目标

- 扫描目标必须同时通过主机、IP 网段、端口和路径白名单，默认只允许本地 DVWA。
- 禁止自动跟随重定向，防止扫描范围在请求过程中发生变化。
- Cookie 通过隐藏输入或环境变量提供，严格校验且不进入输出与报告。
- 对请求次数、速率、超时、响应大小和参数数量设置硬限制。
- 延时检测默认禁用，只有授权配置和命令行同时允许时才执行。
- 使用成对布尔条件、重复采样和置信度降低误报，不将启发式结果表述为绝对结论。
- 报告只保留必要证据，敏感数据脱敏，使用原子写入和限制性文件权限。

## 验收方式

- 通过单元测试证明非授权主机、越界路径、内嵌凭据、非法 Cookie 会被拒绝。
- 通过本地 HTTP 测试服务证明重定向、超大响应和请求超额会被安全策略中止。
- 通过伪造的可控响应验证 SQL 报错与布尔差分检测。
- 检查终端输出和生成报告，确认不包含测试 Cookie。
- 在授权的本地 DVWA 上进行手工集成验证，并保留扫描记录。
