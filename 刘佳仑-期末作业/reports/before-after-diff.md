# 整改前后对比说明

| 安全领域 | 整改前 | 整改后 | 安全收益 |
| --- | --- | --- | --- |
| 扫描授权 | 接受任意 URL | 必须同时匹配主机、IP 网段、端口和路径 | 降低未授权扫描风险 |
| SSRF | 不检查 IP 类型 | 拒绝公网、link-local、multicast、unspecified 和越界网段 | 防止访问公网与云元数据 |
| 重定向 | `urllib` 默认跟随 | 所有 3xx 重定向均安全中止 | 防止初始合法 URL 跳转到越界目标 |
| Cookie 输入 | `--cookie` 明文命令行参数 | 隐藏输入或环境变量 | 减少 Shell 历史和进程列表泄露 |
| Cookie 校验 | 非法片段被忽略 | 非法名称、控制字符、缺失等号和重复名称均拒绝 | 防止请求头注入和静默误配 |
| HTTP 代理 | 使用系统环境代理 | 显式禁用代理 | 避免 Cookie 与靶场请求交给未授权代理 |
| 请求额度 | 无全局上限 | 配置有界上限，每次请求前检查 | 降低误操作与拒绝服务风险 |
| 请求速率 | 无间隔 | 使用单调时钟强制最小间隔 | 降低对靶场与数据库的瞬时压力 |
| 响应大小 | `read()` 无上限 | 有界读取，超限后中止 | 降低内存耗尽风险 |
| 延时 Payload | 默认执行 | 配置和 CLI 双重授权 | 降低数据库资源消耗 |
| 输入处理 | 仅检查是否有 Query | 限制 Scheme、URL/Query 长度、参数数量、路径和控制字符 | 降低注入、资源消耗与边界绕过风险 |
| 检测证据 | 单次基线、简单长度比较 | 两次基线、SQL 报错、布尔真/假成对差分和置信度 | 降低单次抖动导致的误报 |
| 结果保存 | 仅终端输出 | JSON 和 Markdown 结构化报告 | 便于审查、PR 留痕和人工复核 |
| 报告敏感数据 | 无系统脱敏模型 | 数据模型不接收 Cookie，不保存 Query 值和响应原文 | 降低扫描证据二次泄露 |
| 报告文件 | 无 | 原子写入、`0600` 权限、限定个人 reports 目录 | 降低部分写入、越界覆盖与本机泄露 |

## 验证对比

### 整改前行为

- 对任意 `--url` 发出请求。
- Cookie 完整显示在启动命令中。
- 服务端返回大响应时全部读入内存。
- 延时 Payload 无需额外授权。

### 整改后行为

- 公网 URL 在建立网络连接前返回「目标主机不在授权白名单」。
- Cookie 通过隐藏输入读取，终端和报告不显示其值。
- 重定向、超大响应和请求超额触发可记录的安全中止。
- 未获得双重授权时，延时检测不会发送。

## 结论

本次改造不是简单增加一个参数或修改 README，而是将无边界的扫描脚本改造为具有授权、最小权限、凭据保护、资源管理、证据分级和安全留痕能力的模块化工具。
