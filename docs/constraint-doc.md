# 项目约束文档

## 背景说明

当前仓库包含多个信息安全课程实践模块。本次修改对象是 Flask 实现的桌面宠物待办清单。该模块会保存用户待办内容，属于需要身份认证和访问控制保护的数据。

## 任务范围

- 新增用户注册/登录模块。
- 为现有待办接口新增权限校验逻辑。
- 修改原有缺少认证控制的待办模块，写出安全加固版本。
- 新增需要身份验证才能访问的功能接口。
- 更新 README、docs 和 reports 中的过程材料。

## 安全约束

- 不允许在代码、README 示例或提交记录中写入真实密码、密钥或 Cookie。
- 注册密码不能明文保存，必须使用随机盐和密码哈希。
- 登录失败返回统一错误，不暴露用户名是否存在。
- 未登录访问待办数据接口必须返回 `401`。
- 当前用户只能访问自己的待办数据，不得使用全局共享状态文件承载多用户任务。
- 前端不得将密码写入 `localStorage` 或 `sessionStorage`。
- 安全控制必须落在后端接口层，不能只依赖前端隐藏按钮或页面。
- Flask debug 模式默认关闭。

## 禁止行为

- 禁止硬编码默认管理员账号或密码。
- 禁止把认证判断只写在 JavaScript 中。
- 禁止明文保存密码。
- 禁止将 `.env`、密钥、证书、本地数据库等敏感文件提交到仓库。
- 禁止为通过测试而绕过登录检查。

## 验收条件

- 用户可以通过 `/api/register` 注册账号。
- 用户可以通过 `/api/login` 登录，登录后建立 session。
- 未登录请求 `GET /api/state` 和 `GET /api/account/summary` 返回 `401`。
- 登录后可以访问待办接口和账号概览接口。
- 不同用户的待办数据相互隔离。
- 登出后再次访问受保护接口返回 `401`。
