# 风险分析记录

## 选定模块

桌面宠物待办清单：`成员代码/桌面宠物待办清单-陈柯睿/`

本次 PR 负责安全加固与功能扩展，目标是将原本公开访问的待办模块改造为包含用户注册、登录、接口权限校验和用户数据隔离的版本。

## 涉及的敏感操作

- 用户注册：写入用户名和密码凭据。
- 用户登录：校验凭据并建立服务端会话。
- 读取待办数据：`GET /api/state`。
- 新增、修改、删除待办：`POST /api/todos`、`PATCH /api/todos/<todo_id>`、`DELETE /api/todos/<todo_id>`。
- 查看账号概览：`GET /api/account/summary`，该接口只能由已登录用户访问。
- 本地 JSON 文件读写：`data/users.json` 与 `data/user-states/`。

## 主要安全风险

1. 未授权访问风险

   原接口不需要登录即可读取和修改待办数据。如果服务暴露到局域网或公网，其他人可以直接访问接口，读取任务内容或篡改任务状态。

2. 明文或硬编码密码风险

   注册登录模块如果直接保存明文密码，或在代码中写入默认密码，会导致凭据泄露和后续无法安全轮换。

3. 越权访问风险

   增加用户体系后，如果仍然使用单一 `state.json`，不同用户可能读取或修改同一份待办数据，造成横向越权。

4. 默认状态浅拷贝风险

   如果通过 `DEFAULT_STATE.copy()` 为新用户创建状态，只会复制最外层字典，`todos` 这类内层可变对象仍会共享引用。用户 A 新增待办时，用户 B 的默认状态可能看到同一个列表中的内容，造成隐蔽的数据串扰。

5. 错误响应泄露风险

   登录失败时如果明确提示“用户名不存在”或返回内部异常，可能帮助攻击者枚举账号或了解内部实现。

## 安全目标

- 实现用户注册和登录模块。
- 待办接口必须登录后才能访问。
- 待办数据按用户隔离存储，当前用户只能访问自己的数据。
- 默认状态创建必须返回全新的字典、列表及其他可变对象，不能共享 `DEFAULT_STATE` 内部引用。
- 密码使用 PBKDF2 和随机盐保存哈希，不能明文保存。
- 新增一个必须身份验证才能访问的账号概览接口。
- 登录失败和未授权访问返回明确但不过度暴露细节的错误信息。
