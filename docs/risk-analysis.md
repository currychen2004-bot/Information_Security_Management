# 风险分析记录

## 选定模块

桌面宠物待办清单：`成员代码/桌面宠物代办清单-陈柯睿/`

本次 PR 负责的环节是安全整改与功能加固，重点处理待办数据接口缺少身份验证的问题。

## 涉及的敏感操作

- 读取本地待办数据：`GET /api/state`
- 新增待办：`POST /api/todos`
- 修改待办完成状态：`PATCH /api/todos/<todo_id>`
- 删除待办：`DELETE /api/todos/<todo_id>`
- 清除已完成待办：`POST /api/todos/clear-done`
- 读取本地 JSON 数据文件：`data/state.json`

## 主要安全风险

1. 未授权访问风险

   原接口不需要登录即可读取和修改待办数据。如果服务被暴露到局域网或公网，其他人可以直接访问接口，读取任务内容或篡改任务状态。

2. 硬编码凭据风险

   如果为了快速加登录而把密码写死在代码中，密码会随仓库传播，后续很难安全轮换，也容易被误用到真实环境。

3. 调试模式误用风险

   Flask debug 模式包含交互式调试能力，如果误用于非本地环境，可能扩大攻击面。

4. 错误响应泄露风险

   登录失败或未授权访问时，不应返回过多内部实现细节，例如本地文件路径、环境变量值或异常堆栈。

## 安全目标

- 待办数据接口必须在登录后才能访问。
- 访问密码必须通过环境变量配置，不提交到仓库。
- 登录失败和未登录访问返回明确但不过度暴露细节的错误信息。
- 保持原有添加、完成、删除、清除待办等功能行为不变。
