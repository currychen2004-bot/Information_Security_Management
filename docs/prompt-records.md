## 关键 Prompt：完整安全加固约束

```text
为 Flask 桌面宠物待办模块实现完整安全加固，而不是简单本地访问密码。
必须完成：
1. 新增用户注册/登录模块。
2. 为现有待办接口新增权限校验逻辑。
3. 修复原模块接口公开访问的问题，写出安全加固版本。
4. 新增一个必须登录才能访问的功能接口。

约束：
- 密码不能明文保存，不能硬编码默认账号。
- 密码需要使用随机盐和安全哈希。
- 未登录访问受保护接口返回 401。
- 登录失败不能暴露用户名是否存在。
- 不同用户的待办数据必须隔离。
- 前端不能把密码写入 localStorage 或 sessionStorage。
- 安全控制必须在后端接口层实现。
```

## AI 生成结果中的安全相关片段

- 新增 `/api/register`、`/api/login`、`/api/logout`、`/api/session`。
- 新增 `/api/account/summary`，作为必须登录才能访问的功能接口。
- 新增 `login_required` 装饰器，保护现有待办接口。
- 用户密码使用 `hashlib.pbkdf2_hmac()`、随机盐和迭代次数保存哈希。
- 用户数据保存在 `data/users.json`，待办状态按用户 ID 保存到 `data/user-states/`。
- 登录失败统一返回“用户名或密码不正确”，避免账号枚举。

## 发现偏差或问题时的处理

初始实现只使用单一环境变量访问密码，不能满足“新增用户注册/登录模块”和“多用户权限校验”的要求。因此本次进一步整改为真正的用户注册登录模块，并将待办数据从全局状态文件改为按用户隔离存储。

## 人工审查后的二次整改

人工安全审查发现默认状态对象存在潜在浅拷贝风险：如果使用 `DEFAULT_STATE.copy()` 创建新用户状态，`todos` 列表等内层可变对象仍可能被多个状态对象共享，导致不同用户待办数据串扰。

处理方式：

- 新增 `create_default_state()`，使用 `copy.deepcopy(DEFAULT_STATE)` 生成完全独立的默认状态。
- `load_state()` 在用户状态文件不存在时统一调用 `create_default_state()`。
- 增加双用户隔离测试：用户 A 新增待办并退出，用户 B 注册登录后看不到 A 的待办；用户 B 新增待办后，重新登录 A，A 的待办不受影响。
- 增加默认状态工厂测试，验证两个默认状态的 `todos` 列表不是同一个对象。

验证结果：在 `成员代码/桌面宠物待办清单-陈柯睿` 下执行 `pytest -q`，结果为 `13 passed in 0.27s`。
