# 整改说明与验证记录

## 问题是什么

桌面宠物待办模块原本所有接口均可直接访问。只要知道接口路径，未登录用户就可以读取 `data/state.json` 中的待办内容，或通过接口新增、修改、删除任务。

这属于缺少身份认证和访问控制的问题。进一步分析后，简单的单一访问密码不能满足作业中“新增用户注册/登录模块”和“接口权限校验”的要求，因此需要改造成真正的用户体系。

## 怎么改

- 新增用户注册接口 `/api/register`。
- 新增登录、登出和会话状态接口 `/api/login`、`/api/logout`、`/api/session`。
- 密码使用 PBKDF2、随机盐和迭代次数保存哈希，不保存明文密码。
- 新增 `login_required` 装饰器，对待办数据接口统一做后端认证检查。
- 将待办数据按用户 ID 保存到 `data/user-states/`，避免不同用户共享同一份状态。
- 新增登录后才能访问的 `/api/account/summary` 接口。
- 前端新增注册/登录表单，登录后再加载待办功能。
- 审查中发现如果使用 `DEFAULT_STATE.copy()` 创建默认状态，只会复制外层字典，内层 `todos` 列表仍可能被多个用户状态对象共享。已新增 `create_default_state()`，通过 `copy.deepcopy(DEFAULT_STATE)` 为每次默认状态创建独立的字典、列表和其他可变对象。

## 改完应满足什么条件

- 未登录访问待办数据接口返回 `401`。
- 未登录访问账号概览接口返回 `401`。
- 用户可以注册并登录。
- 登录后可以正常使用原有待办功能。
- 不同用户的待办数据相互隔离。
- 登出后会话失效，再次访问待办接口返回 `401`。
