# 安全审查清单

## 第一层：对照 Prompt 检查

| 检查项 | 结果 | 说明 |
| --- | --- | --- |
| 是否实现登录保护 | 通过 | 新增 `/api/login`、`/api/logout`、`/api/session` |
| 待办数据接口是否需要登录 | 通过 | `GET /api/state` 及写操作接口均添加 `@login_required` |
| 是否避免硬编码密码 | 通过 | 访问密码从 `PET_TODO_PASSWORD` 读取 |
| 前端是否持久化密码 | 通过 | 密码只在登录请求中提交，不写入 localStorage/sessionStorage |
| 未登录是否返回 401 | 通过 | `login_required` 统一返回 `401` |
| 原有待办功能是否保留 | 通过 | 登录后新增、完成、删除等主流程保持可用 |

## 第二层：人工安全审查

| 检查项 | 结果 | 说明 |
| --- | --- | --- |
| 认证控制是否在后端 | 通过 | 前端隐藏界面只是体验优化，真正拦截在 Flask API |
| 最小权限原则 | 通过 | 只新增访问待办模块所需的登录会话，不引入额外管理权限 |
| 错误响应是否过度暴露 | 通过 | 未登录、密码错误、未配置密码均不返回堆栈或环境变量值 |
| 敏感配置是否进入仓库 | 通过 | README 使用占位示例，`.gitignore` 已排除 `.env` 等文件 |
| 调试模式是否默认关闭 | 通过 | 只有 `FLASK_DEBUG=1` 时才开启 debug |

## 剩余风险

- 当前认证适合课程演示和本地使用，不适合直接作为公网生产认证系统。
- 未实现登录失败次数限制，若部署到真实网络环境，需要增加限速或锁定策略。
- 未引入 HTTPS，公网部署时需要由反向代理或部署平台提供 TLS。
