# 安全审查清单

## 第一层：对照 Prompt 检查

| 检查项 | 结果 | 说明 |
| --- | --- | --- |
| 是否新增注册接口 | 通过 | 新增 `POST /api/register` |
| 是否新增登录接口 | 通过 | 新增 `POST /api/login` |
| 现有待办接口是否增加权限校验 | 通过 | 待办读取、创建、修改、删除、清理和宠物反馈接口均添加 `@login_required` |
| 是否修复原模块公开访问问题 | 通过 | 未登录访问受保护接口返回 `401` |
| 是否新增需身份验证的功能接口 | 通过 | 新增 `GET /api/account/summary` |
| 是否避免明文密码 | 通过 | 使用 PBKDF2、随机盐和迭代次数保存密码哈希 |
| 是否避免前端持久化密码 | 通过 | 密码只在登录/注册请求中提交 |

## 第二层：人工安全审查

| 检查项 | 结果 | 说明 |
| --- | --- | --- |
| 认证控制是否在后端 | 通过 | 前端隐藏界面只是体验优化，真正拦截在 Flask API |
| 用户数据是否隔离 | 通过 | 待办状态按用户 ID 存储在 `data/user-states/` |
| 默认状态是否避免共享可变对象 | 通过 | `create_default_state()` 使用 `copy.deepcopy(DEFAULT_STATE)`，每次生成独立的 `todos` 列表 |
| 是否覆盖双用户隔离回归测试 | 通过 | 测试流程覆盖用户 A 新增、退出、用户 B 验证不可见、用户 B 新增、重新登录 A 验证不受影响 |
| 是否存在账号枚举风险 | 基本通过 | 登录失败统一返回“用户名或密码不正确” |
| Session Cookie 是否有基础安全属性 | 通过 | 显式配置 `HttpOnly` 和 `SameSite=Lax` |
| 调试模式是否默认关闭 | 通过 | 只有 `FLASK_DEBUG=1` 时才开启 debug |
| 敏感配置是否进入仓库 | 通过 | 未提交真实密码、密钥或 `.env` |

## 剩余风险

- 当前认证适合课程演示和本地小型应用，不适合直接作为公网生产认证系统。
- 未实现登录失败次数限制，若部署到真实网络环境，需要增加限速或锁定策略。
- 未引入 HTTPS，公网部署时需要由反向代理或部署平台提供 TLS。
